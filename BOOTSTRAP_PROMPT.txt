### 2. 核心指令 (Core Mandates)
- **无损更新 (Lossless Update)**：**绝对禁止**在回写文件时使用 `...` 或省略号替代现有代码/文档。修改必须包含全量内容或通过原子化工具精准定位，确保 100% 保留所有已存在的 User Stories、验收标准和代码逻辑。
- **去工业化 (De-industrialize)**：绝对禁止在用户界面使用制造业术语（如 MO, BOM）。必须通过 `farm_ux` 映射为农业术语（Intervention, Recipe）。
- **空间优先 (Spatial First)**：地块与网格操作必须基于 PostGIS，遵循 `farm_core` 的空间规范。
- **禁止不可控编辑 (Strict Edit Control)**：禁止对超过 5 行的逻辑使用 `replace`。必须使用 `run_shell_command` 配合 `sed`/`awk` 定位，或通过 `read_file` 全量读取后 `write_file` 回写。
- **职责分离与 DRY**：核心层（元数据）、行业层（业务规则）、表现层（UI）必须物理隔离。通用计算必须沉淀为 Mixin。
- **文档即真理 (Doc-Driven)**：一切算法必须有 `docs/algorithms/` 下的规格文档支持。
- **原子化提交 (Atomic Commit)**：**强制要求**代码修改与文档更新（如 User Story、算法规格）分开提交。严禁将逻辑变更与文档说明混在同一个 Git Commit 中。**所有 Git Commit Message 必须使用英文编写**，以确保国际化协作的标准化。
- **模块化架构 (Modular Architecture)**：**强制要求**单个 Python 文件行数不超过 500 行。如果超过 500 行，必须进行拆分，将功能模块化为多个服务类或拆分到单独的模块文件中，以保持代码的可维护性。
- **禁止 Co-author (No Co-author)**：**强制要求**在 Git 提交时不得使用 co-author 标签。所有提交应只反映实际贡献者，保持提交历史的清晰性。
