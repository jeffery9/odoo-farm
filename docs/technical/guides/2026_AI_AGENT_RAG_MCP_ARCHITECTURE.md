# 技术专题：基于 RAG 与 MCP 的农业自主智能体架构
*Status: Draft (2026-01-31)*

## 1. 架构目标 (Overview)
为了将 Odoo 复杂的业务逻辑与 AI 智能体（LLM）高效连接，我们采用了 **RAG (检索增强生成)** 与 **MCP (Model Context Protocol)** 的双轮驱动架构。
- **RAG** 解决“知识召回”：提供非结构化的农事智慧与历史背景。
- **MCP** 解决“能力执行”：提供标准化的工具调用与结构化业务数据快照。

## 2. 业务数据提供路径 (Data Provisioning)

### 2.1 结构化数据：MCP Server for Odoo
我们通过在 Odoo 中实现一个原生 MCP Server，将业务数据暴露为“资源”和“工具”：

| MCP 组件 | Odoo 对应物 | 业务示例 |
| :--- | :--- | :--- |
| **Resources** | 业务模型快照 (URI) | `odoo://stock.lot/LOT2026001` - 获取批次详情 |
| **Tools** | Mixin 计算接口 | `call_compute_carbon_footprint(lot_id)` - 获取碳排放 |
| **Context** | 权限与信誉分 | 只有信誉分 > 800 的 Agent 能访问 `cost_price` |

#### 数据流转逻辑：
1. **URI 订阅**：Agent 通过 MCP 订阅感兴趣的地块或批次。
2. **实时映射**：MCP Server 将 Odoo Model 转换为标准 JSON-RPC 载荷，并通过 `AgriViewMixin` 进行术语过滤。
3. **反馈执行**：Agent 调用 MCP Tools 修改业务状态（如：创建 `Intervention`）。

### 2.2 非结构化知识：RAG 向量化闭环
利用 RAG 解决 Agent 对历史记录和专业手册的理解：

1. **Embedding Mixin**：在 `farm.knowledge` 和 `mail.message` (Chatter) 中挂载。
2. **知识碎片化**：将长文档切分为符合 LLM Context Window 的 Chunk。
3. **语义检索**：Agent 在决策前，通过 `llm_service` 发起语义搜索，系统返回最相关的 Top-N 历史片段。

## 3. "Your Machine, Your Rules" 安全机制
在 MCP 与 RAG 层强制执行以下红线：
- **数据脱敏**：所有通过 MCP 流出的数据必须剥离工业化原生字段（如 `efficiency_factor`），仅保留农业语义字段。
- **动态授权 (`allowed_tools`)**：基于 `PlanAPI` 的握手协议，Agent 必须声明其意图，系统动态返回该次会话可用的 MCP Tools 列表。
- **证据审计 (`EvidenceAnalyzer`)**：Agent 通过 MCP 提交的任何业务修改，必须携带物理存证（如 GPS），否则不予清算。
