# VRA (Variable Rate Application) 变量作业落地方案与实现路线

## 1. 核心目标
将 Odoo 从静态的“行政财务中心”升级为动态的“空间数据指挥中心”，实现基于地块内部空间差异（土壤养分、长势、病虫害）的精准投入品（肥、药、水、种）管理。

## 2. 五阶段实现路线

### 第一阶段：基础设施空间化 (Spatial Foundation)
*   **PostGIS 启用**：在 PostgreSQL 数据库中启用 PostGIS 扩展，支持空间地理运算与空间索引。
*   **地块模型升级**：将 `farm.location` 模型中的边界字段从普通 Text 升级为 `Geometry(Polygon, 4326)` 类型。
*   **网格化系统 (The Grid)**：建立网格化逻辑，支持将大面积地块自动切割为 5m×5m 或 10m×10m 的独立计算单元（Cell）。
*   **GIS 视图集成**：在 Odoo PWA 端集成 `Leaflet.js` 视图，实现地块网格的空间可视化预览。

### 第二阶段：感知层集成 (The Science Data)
*   **卫星遥感自动化**：对接 Sentinel-2 或 Google Earth Engine API，实现 NDVI（植被指数）等长势数据的定期抓取与网格映射。
*   **土壤养分插值**：引入 `scipy.interpolate` 库，利用克里金（Kriging）等算法将离散的土壤采样点数据转化为覆盖全网格的养分图层。
*   **气象与积温集成**：结合气象数据计算地块内的微气候积温（GDD），作为生长阶段判断的科学依据。

### 第三阶段：变量决策引擎 (Prescription Engine)
*   **VRA 策略模型**：建立“数据-决策”配置表，允许农技专家定义逻辑（如：当 NDVI < 阈值且土壤肥力低时，增加施肥量系数）。
*   **处方图 (Prescription Map) 生成**：基于农学算法自动计算全网格的目标作业量，生成多色阶热力图。
*   **人工干预 UI**：在地图视图中提供“笔刷”工具，允许用户根据经验手动调整特定网格区域的用量。

### 第四阶段：指令下发与硬件对接 (Execution)
*   **标准格式导出**：
    *   **Shapefile (.shp)**：导出带有 `Rate` 属性的空间矢量文件，适配主流国产农机终端。
    *   **ISO-XML (ISOBUS)**：实现符合 ISO 11783 标准的协议转换，对接高端欧美农机设备。
*   **IoT 实时流控**：针对通过 `farm_iot` 模块改装的简易设备，通过 MQTT/WebSocket 协议实时推送“当前坐标-对应速率”指令。
*   **离线保障**：在 PWA 离线模式下缓存地图瓦片和处方数据，确保在无网络作业环境下依然可用。

### 第五阶段：数据闭环与财务核销 (Closing the Loop)
*   **实喷图 (As-Applied Map) 解析**：自动解析农机回传的作业轨迹与实际喷施日志（.log / .jdl）。
*   **偏差分析**：在网格层面对比“处方计划”与“实喷结果”，评估作业质量。
*   **自动业财核销**：根据实喷总量自动触发 Odoo 库存扣减、成本分摊及 MRP 完工结转，确保账实相符。

## 3. 技术架构建议
*   **后端栈**：Python + PostGIS + GeoPandas + Rasterio (栅格处理)。
*   **前端栈**：Odoo PWA + Leaflet.js + Leaflet.draw + Chart.js。
*   **协议层**：MQTT (实时) + ISOBUS (标准接口)。

## 4. 实施里程碑
1.  **M1 (基础设施阶段)**：完成 PostGIS 升级与地块网格化逻辑。
2.  **M2 (科学感知阶段)**：完成卫星 NDVI 自动同步与网格映射。
3.  **M3 (指令执行阶段)**：完成 Shapefile 导出与作业后的库存闭环。
