# 史诗 1：农业基础主数据 (Agricultural Master Data)
*目标：建立“万物皆产品”的农业资源体系，支撑多业态核算。*

1. **[US-01-01] 多业态活动分类**：✅ 已完成 (2026-01-14)
    - **描述**：作为农场主，我希望定义种植、畜牧、水产、农旅等活动家族。
    - **验收条件**：
        - 必须通过 `project.project` 继承实现，支持通过 `Selection` 字段区分家族。
        - **(Odoo Mapping)** 每个家族必须关联独立的 `ir.sequence`，确保任务编号（如 P001, L001）不冲突。
        - UI 必须支持根据家族类型动态加载特定的字段组（Properties）。

2. **[US-01-02] 农业 UOM (计量单位) 弹性转换**：✅ 已完成 (2026-01-14)
    - **描述**：作为农场主，我希望在库存显示“吨”，而在施肥任务中自动根据密度显示为“斤/亩”。
    - **验收条件**：
        - **(Logic)** 实现基于地块 `land_area` 的动态换算逻辑。
        - 施肥/喷洒类产品必须维护 `standard_dose`（标准用量）和 `dose_uom_id`。
        - 任务界面确认时，必须自动计算并展示“预期总消耗量”，且支持双语单位显示。

3. **[US-01-03] 地块 GIS 数字化**：✅ 已完成 (2026-01-14)
    - **描述**：作为农场主，我希望在系统中定义地块，记录面积、土壤类型及地理坐标。
    - **验收条件**：
        - 地块必须继承 `stock.location` 并在 GIS 图层中可被 GeoJSON 描述。
        - 土壤 N/P/K 指标必须通过 `farm.soil.analysis` 模型实现，支持历史趋势图对比。

4. **[US-01-04] 生物资产全生命周期系谱**：✅ 已完成 (2026-01-14)
    - **描述**：作为技术员，我管理动物/植株的个体或群组，记录出生、性别及品种。
    - **验收条件**：
        - 必须使用 `stock.lot` 承载，支持 `father_id` 和 `mother_id` 递归查询。
        - 系谱变更必须强制触发 `mail.tracking.value` 审计日志。

5. **[US-01-05] 繁育代次追踪 (G0-G3)**：✅ 已完成 (2026-01-14)
    - **描述**：作为种业技术员，我希望标记种子/种畜的繁育代次，系统需硬性拦截非商品代次的违规销售。
    - **验收条件**：
        - `sale.order` 确认时（action_confirm），系统必须循环校验明细行批次的 `agri_generation`。
        - **(Activity)** 若检测到代次违规，除了 ValidationError 拦截，还必须自动向“合规主管”创建一条异常审查 Activity。

6. **[US-01-06] 生物资产成龄转固核算**：✅ 已完成 (2026-01-14)
    - **描述**：作为财务，我希望定义资产成熟节点（如：进入产果期），系统自动将育苗成本结转为固定资产原值。
    - **验收条件**：
        - 必须集成 `account.asset` 逻辑。
        - 达到 `maturity_age_days` 时，系统自动触发 `account.move` 分录，将累计的 WIP 成本（生产成本）结转至固定资产科目。

7. **[US-01-07] 生物资产估值与折旧模型**：✅ 已完成 (2026-01-14)
    - **描述**：作为财务，我希望为多年生作物（如茶树）或种畜设置折旧年限，并根据生长阶段自动调整其价值。
    - **验收条件**：
        - 资产卡片必须支持“生长阶段价值系数”配置。
        - 报表输出必须符合“中英双语 / Dual-language”标准。

8. **[US-01-08] “一键初始化”行业主数据包**：✅ 已完成 (2026-01-25)
    - **描述**：作为新用户，我希望根据我的行业（如：柑橘种植、生猪养殖），一键导入标准品种库、生理阶段定义及常用的农业 UoM 换算表。
    - **验收条件**
        - **(Data)** 预置至少 5 个细分行业的基础数据包。
        - **(Logic)** 导入过程支持“属性映射”：自动将行业标准的生理周期关联至 Odoo 的任务模板。

9. **[US-01-09] 土地健康与轮作档案**：💡 待规划 (Backlog from SAP)
    - **描述**：作为农场主，我希望记录每一块土地的历史种植作物、连作障碍评分及 N/P/K 消耗趋势，以制定科学的轮作计划。
    - **验收条件**：
        - **(GIS)** 地块模型必须集成“种植历程时间轴”视图。
        - **(Logic)** 自动根据过去 3 年的种植史，在当前 Campaign 规划时发出“连作障碍”风险预警。
        - 支持记录土壤重金属、理化指标的历史变化曲线图。
