# EPIC 080:层级视图容器与多维管理视角 (Hierarchy View Containers)
*目标：通过逻辑容器解耦物理隶属关系，实现基于不同管理视角（地理、战略、功能）的穿透式绩效汇总。*

---

## 业务价值
- **核心价值**: 通过逻辑容器解耦物理隶属关系，实现基于不同管理视角（地理、战略、功能）的穿透式绩效汇总，提升大型集团化农场的管理效率
- **目标用户**: 集团管理员、运营总监、财务总监、安全员、场长、合作社理事长
- **量化收益**: 通过灵活的管理视角实现跨资产对标，支持战略审计和管理下钻，提升集团化农场管理效率和决策质量

## 技术挑战
- **复杂性**: 需要处理逻辑容器管理、树状层级嵌套、跨模型聚合等复杂技术
- **性能要求**: 大规模数据的层级汇总和透视分析需高效响应
- **安全合规**: 需要符合数据权限管理和跨公司数据访问相关法规要求
- **集成难点**: 与权限控制、绩效计算、多维分析等系统的集成

---

## 2. 用户故事 (User Stories)

1. **[US-080-01] 逻辑管理容器 (Logical View Containers)**：✅ 已完成 (2026-01-25)
    - **描述**：作为集团管理员，我希望创建逻辑容器，将不属于同一物理农场的资产划归到同一管理视角。
    - **验收条件**：
        - 容器模型 (`farm.hierarchy.view`) 必须支持多对多挂载 `farm.location` 和 `farm.resource`。
        - **(Logic)** 资产与容器的关联必须是“非排他性”的：一个地块可以同时属于多个视角。

2. **[US-080-02] 树状层级嵌套 (Recursive Nesting)**：✅ 已完成 (2026-01-25)
    - **描述**：作为运营总监，我希望通过父子容器构建层级管理树。
    - **验收条件**：
        - 支持无限层级递归关联 (`parent_id`)。
        - 视图层级必须能以“面包屑（Breadcrumbs）”或“树状组件”进行展示。

3. **[US-080-03] 跨模型 OPE 聚合引擎 (Cross-model Aggregation)**：✅ 已完成 (2026-01-25)
    - **描述**：作为财务总监，我打开一个容器时，系统应自动汇总该视角下所有资产、资源及子容器的平均绩效。
    - **验收条件**：
        - **(Logic)** 必须继承 `farm.ope.mixin` 计算框架。
        - **(Automation)** 提供 `action_calculate_view_performance` 手动触发及定时更新逻辑。
        - 支持“面积加权”滚动汇总。

4. **[US-080-04] 容器级权限控制 (Container-based Permissions)**：✅ 已完成 (2026-01-25)
    - **描述**：作为安全员，我希望限制特定用户仅能查阅其被授权容器内的数据及其下属节点。
    - **验收条件**：
        - **(Security)** 实现基于容器 ID 的 Odoo `ir.rule`。
        - 用户在列表视图中自动被过滤，仅能看到其职责范围内的管理视角。

5. **[US-080-05] 跨视角性能对标分析 (Perspective Benchmarking)**：✅ 已完成 (2026-01-25)
    - **描述**：作为场长，我希望在同一报表中对比"传统地块"容器与"数字化变量地块"容器的 OPE 指标。
    - **验收条件**：
        - **(Pivot)** 提供支持"视图容器"作为行维度的多维透视分析。
        - 结果必须支持导出为双语标准。

6. **[US-080-06] 跨公司管理视角 (Cross-company Perspectives)**：✅ 已完成 (2026-01-25)
    - **描述**：作为合作社理事长，我希望创建一个包含所有社员农场资产的统一视图，以便进行全局绩效对标。
    - **验收条件**：
        - 容器支持取消 `company_id` 限制（或设置为全局共享）。
        - **(Logic)** OPE 汇总引擎必须能自动穿透至下属所有 Company 的数据进行加权计算。
