# 史诗 50：层级视图容器与多维管理视角 (Hierarchy View Containers)
*目标：通过逻辑容器解耦物理隶属关系，实现基于不同管理视角（地理、战略、功能）的穿透式绩效汇总。*

---

## 1. 业务价值 (Business Value)
在大型集团化农场中，物理资产的隶属关系往往无法满足多元化的管理需求。通过引入“视图容器”，管理者可以：
- **灵活对标**：从“品种视角”对比不同地块的种植效能。
- **战略审计**：从“有机认证”视角查看所有受证地块的全球表现。
- **管理下钻**：从集团指标一键下钻至具体网格的原始数据。

---

## 2. 用户故事 (User Stories)

1. **[US-50-01] 逻辑管理容器 (Logical View Containers)**：✅ 已完成 (2026-01-25)
    - **描述**：作为集团管理员，我希望创建逻辑容器，将不属于同一物理农场的资产划归到同一管理视角。
    - **验收条件**：
        - 容器模型 (`farm.hierarchy.view`) 必须支持多对多挂载 `farm.location` 和 `farm.resource`。
        - **(Logic)** 资产与容器的关联必须是“非排他性”的：一个地块可以同时属于多个视角。

2. **[US-50-02] 树状层级嵌套 (Recursive Nesting)**：✅ 已完成 (2026-01-25)
    - **描述**：作为运营总监，我希望通过父子容器构建层级管理树。
    - **验收条件**：
        - 支持无限层级递归关联 (`parent_id`)。
        - 视图层级必须能以“面包屑（Breadcrumbs）”或“树状组件”进行展示。

3. **[US-50-03] 跨模型 OPE 聚合引擎 (Cross-model Aggregation)**：✅ 已完成 (2026-01-25)
    - **描述**：作为财务总监，我打开一个容器时，系统应自动汇总该视角下所有资产、资源及子容器的平均绩效。
    - **验收条件**：
        - **(Logic)** 必须继承 `farm.ope.mixin` 计算框架。
        - **(Automation)** 提供 `action_calculate_view_performance` 手动触发及定时更新逻辑。
        - 支持“面积加权”滚动汇总。

4. **[US-50-04] 容器级权限控制 (Container-based Permissions)**：✅ 已完成 (2026-01-25)
    - **描述**：作为安全员，我希望限制特定用户仅能查阅其被授权容器内的数据及其下属节点。
    - **验收条件**：
        - **(Security)** 实现基于容器 ID 的 Odoo `ir.rule`。
        - 用户在列表视图中自动被过滤，仅能看到其职责范围内的管理视角。

5. **[US-50-05] 跨视角性能对标分析 (Perspective Benchmarking)**：✅ 已完成 (2026-01-25)
    - **描述**：作为场长，我希望在同一报表中对比"传统地块"容器与"数字化变量地块"容器的 OPE 指标。
    - **验收条件**：
        - **(Pivot)** 提供支持"视图容器"作为行维度的多维透视分析。
        - 结果必须支持导出为双语标准。

6. **[US-50-06] 跨公司管理视角 (Cross-company Perspectives)**：✅ 已完成 (2026-01-25)
    - **描述**：作为合作社理事长，我希望创建一个包含所有社员农场资产的统一视图，以便进行全局绩效对标。
    - **验收条件**：
        - 容器支持取消 `company_id` 限制（或设置为全局共享）。
        - **(Logic)** OPE 汇总引擎必须能自动穿透至下属所有 Company 的数据进行加权计算。
