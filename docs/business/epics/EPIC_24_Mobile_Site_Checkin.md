# 史诗 24：移动端现场打卡与工时校验 (Mobile Site Check-in)
*目标：确保农事作业真实性，利用移动端 GPS 与拍照能力，实现自动化、高可信的工时核算。*

1. **[US-24-01] 现场地理打卡 (Site Check-in)**：✅ 已完成 (2026-01-14)
    - **描述**：作为农场工人，我希望在到达作业现场时通过手机端进行一键打卡。
    - **验收条件**：
        - 系统自动记录打卡瞬间的 GPS 经纬度及服务器时间。
        - **(PWA)** 打卡界面必须预缓存，确保在零信号地头能瞬间唤起。

2. **[US-24-02] 自动地块匹配校验**：✅ 已完成 (2026-01-14)
    - **描述**：作为管理人员，我希望系统自动判定工人的打卡位置是否在任务分配的地块内。
    - **验收条件**：
        - **(PWA)** 围栏判定算法（射线法）必须在前端本地运行，支持离线即时反馈。

3. **[US-24-03] 自动工时记录同步**：✅ 已完成 (2026-01-14)
    - **描述**：作为农场主，我希望签退（Check-out）动作能自动计算时长并生成工时表。
    - **验收条件**：
        - 签退后自动更新关联任务的作业时长。
        - 同步生成 `hr.timesheet` 记录。

4. **[US-24-04] 现场拍照存证**：✅ 已完成 (2026-01-14)
    - **描述**：作为质量管理员，我要求工人打卡时必须拍摄现场实时照片。
    - **验收条件**：
        - 照片必须带有不可修改的 GPS 与时间水印。
        - 照片自动关联至当前作业批次（US-25-01 联动）。

5. **[US-24-05] 离线打卡支持**：✅ 已完成 (2026-01-14)
    - **描述**：作为工人，我在无网络覆盖区域也能完成打卡，待信号恢复后自动补传。
    - **验收条件**：
        - **(PWA)** 离线状态下本地保存记录，并按顺序补录同步。

6. **[US-24-06] 强制人脸/活体核身 (Core-Closure)**：✅ 已完成 (2026-01-14)
    - **描述**：作为管理人员，我希望关键打卡点必须进行活体核查，杜绝代打卡。
    - **验收条件**：
        - 唤起 PWA 原生生物识别接口（或第三方 SDK）。
        - 非本人强制拦截打卡动作。

7. **[US-24-07] 蓝牙/NFC 自动近场打卡**：✅ 已完成 (2026-01-14)
    - **描述**：作为工人，进入感应区时 App 自动感知并预填打卡信息。
    - **验收条件**：
        - 支持 BLE 信标或 NFC 标签识别。
        - 提升考勤数据的地理真实性。

## 业务价值
- **核心价值**: 实现移动端现场打卡与工时校验，确保农事作业真实性
- **目标用户**: 农场工人、管理人员、HR、财务人员
- **量化收益**: 提高考勤真实性95%以上，降低管理成本，提升工时核算准确性

## 技术挑战
- **复杂性**: 需要处理离线打卡和数据同步逻辑
- **性能要求**: GPS定位和图像处理需快速响应
- **安全合规**: 需要保障工人隐私和数据安全
- **集成难点**: 与现场作业、证据存证等系统的集成
