# Odoo Farm 用户故事精化与业务闭环规划 (US Refinement Strategy - V6.0)

## 1. 核心目标
将原始的功能需求升级为**“实战级农业数字化准则”**。每一个精化后的用户故事（User Story）必须解决农业一线生产中的真实痛点，消除制造业术语摩擦，并提供三端适配（PC/PDA/Mobile）的极致交互体验。

## 2. 精化准则：六维价值模型 (The 6-Dimensional Mapping)

在精化每一个 US 时，必须至少命中以下三个维度，并使用相应的标签标注在“验收条件”中：

| 维度 | 要求说明 | 验收条件标签 |
| :--- | :--- | :--- |
| **农业原子逻辑** | 引入 NPK 平衡、GDD 积温、FCR 模型、Arrhenius 货架期等专业算法。 | `(Logic)` |
| **Odoo 原生映射** | 严禁滥用自定义表，必须明确映射至 `mrp`, `project`, `stock.lot`, `account.move` 等。 | `(Odoo Mapping)` |
| **地头交互约束** | **点选优先、键盘规避**。强制 PWA 离线、手势交互、大触控目标及稳态颜色反馈。 | `(UX)`, `(PWA)` |
| **物联感知安全** | 集成 MQTT 遥测、双人确认逻辑、HACCP 熔断及工业 PDA 硬件按键映射。 | `(IOT)`, `(Hardware)` |
| **品牌合规背书** | 产出可用于审计的数字化凭证、区块链 Hash 指纹及双语溯源门户。 | `(Compliance)`, `(Branding)` |
| **社会化协同** | 涵盖合作社统购统配、内部资金拆借、达人带货归因及 ESG 国际披露。 | `(Cooperative)`, `(ESG)` |

## 3. 用户故事 (US) 统一写作规范

所有 US 文档必须遵循以下 Markdown 结构，确保 100% 格式一致性：

```markdown
数字. **[US-史诗编号-流水号] 故事标题**：✅ 状态 (日期)
    - **描述**：作为[特定角色]，我希望[业务功能]，以便于[解决的痛点/创造的价值]。
    - **验收条件**：
        - **(标签) **条目 1：明确的技术或业务约束（如：响应时间 < 2s）。
        - **(标签) **条目 2：明确的 Odoo 模型映射（如：使用 stock.lot 承载）。
        - **(标签) **条目 3：明确的交互要求（如：PDA 端支持物理 F1 键保存）。
```

## 4. 现场作业 UX 精化准则 (The "No-Keyboard" Rule)

针对移动端和 PDA 的现场作业，精化时必须遵循：
1. **开关驱动 (Toggle-First)**: 二元逻辑必须使用巨型开关，严禁使用下拉框。
2. **增量芯片 (Incremental Chips)**: 数量录入必须提供 `+1`, `+5`, `+10` 的点选芯片，代替软键盘输入。
3. **情境感知 (Contextual Magic)**: 扫码后系统应自动推断下一步动作，实现“一键即达”。
4. **稳态反馈 (Steady Feedback)**: 使用常驻绿色（成功）或全屏淡红（异常）代替闪烁，减少视觉疲劳。

## 5. 跨端适配策略 (Cross-Device View Strategy)

每一个 US 的验收条件必须考虑不同终端的职责边界：
- **PC 端**: 侧重决策分析、多窗口对标及批量配置（复杂表格、Pivot、看板）。
- **手机端**: 侧重任务查阅、扫码作业、现场取证及社交沟通（纵向流、Sticky Header）。
- **PDA 端**: 侧重高频连续扫描、硬件按键触发、极端环境下的三位一体反馈。
