## 2a.1 基础设置与种植注册 (Setup & Registration)

大田种植业务底座通过 `farm_crop` 和 `farm_field_crops` 模块实现。在作物播种前，必须在地块台账中登记地理边界（WKT 格式多边形），并初始化对应的种植周期。

### 2a.1.1 大田与种植周期基础设置业务规程 (Field and Crop Cycle Registration SOP)

*   **地块档案登记流程 (Parcel Registration)**：
    进入大田管理系统，导航至“地块台账（Field Parcels）”菜单，系统触发唯一性档案初始化事务（Transaction Initialization）创建物理地块资产。在表单中，在主数据中登记具备物理确权的多边形边界标识（例如：北方主粮大豆A区）与全局唯一地块编码（例如：PARCEL-NORTH-01）。在“GPS 边界”文本域中，录入标准的 PostGIS WKT 多边形几何数据（例如：`POLYGON((116.39 39.90, 116.40 39.90, 116.40 39.91, 116.39 39.91, 116.39 39.90))`），该数据将直接用于无人机飞防和卫星多光谱地理围栏碰撞计算。设置该地块的土壤肥力初始健康分（默认值为100分）。保存表单时，系统会自动在后台验证地块编码在同一农场实体内的唯一性。
*   **种植周期初始化流程 (Crop Cycle Initialization)**：
    导航至“种植周期（Crop Cycles）”菜单并点击“新建”。输入种植周期名称（例如：大豆 2026 年第一季种植周期），并关联上述登记的地块。指定播种日期（当前播种时间），设定安全间隔期（PHI）下限天数（默认为 15 天），用于农药喷洒后的安全间隔期强制校验。保存记录时，Odoo 自动调用系统序列号生成器在后台分配唯一周期编码（例如：CC-2026-0001）。新创建的种植周期初始阶段状态默认设为“草稿”，累计有效积温（GDD）初始化为 0.0。

### 2a.1.2 界面交互与操作说明 (UI Interaction & Layout Guide)

*   **列表视图操作 (List View Interaction)**：
    在种植周期列表视图下，系统展示周期编码、周期名称、关联地块、播种日期、累计有效积温（GDD）以及当前阶段状态。利用 Odoo 19 原生的布尔值样式装饰器，行数据会根据阶段进行动态着色：“草稿”状态以淡蓝色信息气泡显示，“运行中”状态以绿色成功样式标记，而“采收中”状态则通过醒目的橙色警告标记进行突出。多公司数据隔离在此视图下严格执行，普通操作员仅能查看到自身所属实体的周期台账。
*   **表单视图控制与状态机推进 (Form View & State Machine)**：
    表单顶部设计有面包屑状态进度条和动作控制按钮。状态机转移受严格的权限与业务校验约束。当处于“草稿”阶段时，界面显示“激活周期”按钮，点击后将状态变更为“运行中”；进入“运行中”后，系统自动隐藏激活按钮并显示“启动采收”按钮；点击“启动采收”则将状态推进至“采收中”；在采收阶段，点击“完工关闭”按钮将完成全周期，状态变更为“已完工”。
*   **只读属性与审计 Chatter (Read-only Constraints & Chatter Audit)**：
    为了保证业务数据的物理防篡改属性，一旦种植周期推进到“运行中”或后续阶段，关联地块、播种日期等关键物理属性自动变为“只读”状态，防止人为修改历史档案。若种植周期被推进到“已完工”阶段，则所有基本字段（如名称、安全间隔期等）均会被永久锁定为只读。表单下方的 Odoo Chatter 模块会高频记录每一次阶段转移、字段变动的具体操作人与精确时间戳，并同步派发后续的农艺巡检待办任务。

## 2a.2 物联网架构与遥测闭环 (IoT & Telemetry Loop)

大田环境传感器及卫星传感器数据，通过 LoRaWAN 窄带物联网网关和 HTTP 接收端实现高频灌入。

### 2a.2.1 卫星遥感多光谱监控数据同步规程 (NDVI Satellite Telemetry SOP)

*   **卫星 Webhook 接收与解析规程**：
    当 Sentinel-2 卫星星座通过多光谱传感器扫描完成并计算出目标地块的归一化植被指数（NDVI）栅格数据后，其云端平台自动向 Odoo 的开放物联网 HTTP 接收网关推送同步数据报文。
*   **数据元素与系统处理逻辑**：
    同步报文包含事件类型（归一化植被指数网格计算完成）、数据来源标识（Sentinel-2 遥感 API 接口）、统一的 ISO 协调世界时（UTC）时间戳、以及该地块注册的农实体代码。在负载明细中，报送该地块的唯一地块编码、卫星扫描时的云量覆盖率（例如 1.25%）、卫星多光谱的空间分辨率（例如 10.0 米），以及核心的植被指数统计矩阵，包括平均 NDVI 值（例如 0.74）、最低植被指数、最高植被指数和标准差。此外，报文还包含地表水分压力指数（例如 0.12，数值越高代表干旱缺水越严重）以及估算的单位公顷生物量（例如每公顷 3450.0 公斤）。
*   **Odoo 存储与自愈联动**：
    Odoo 接口解析到报文后，通过地块编码自动检索出处于“运行中”的种植周期。系统自动将最新的平均 NDVI 指标记录在种植周期的时序记录板上。若实测水分压力指数超出设定阈值（例如大于 0.40），系统将自动在当前周期的 Chatter 中生成一条橙色异常警告，并向基地灌溉管理员派发一个“实地查看灌溉管网”的农事待办任务。

### 2a.2.2 LoRaWAN 泥土传感器数据流析规程 (LoRaWAN Soil Telemetry SOP)

*   **LoRaWAN 泥土传感器高频传输逻辑**：
    安装在田间的 LoRaWAN 泥土温湿度 NPK 五合一传感器按照预设频率（例如每 15 分钟一次）向地表物联网基站发送无线射频帧。基站将该射频帧通过 MQTT 协议转发至 ChirpStack 开源物联网解析服务器。
*   **数据帧明细与网络参数监测**：
    解析服务器向 Odoo 的 `farm_iot` 物联网模块发送已被解码的 JSON 明细报文。报文内容包括应用程序 ID（例如“2”）、应用服务组标识（soil-telemetry）、设备注册名称、全球唯一 DevEUI 物理地址。报文还包含了网关接收时的网络诊断指标，如物理网关ID、信号强度指示（RSSI，例如 -85 dBm）、信噪比（SNR，例如 7.5 dB）以及上行射频载波频率（例如 470.3 MHz）。
*   **物理遥测指标映射**：
    报文核心包含传感器直接测得的土壤物理指标：土壤温度（24.5 摄氏度）、土壤水分体积百分比（34.2%）、氮含量（125 毫克/公斤）、磷含量（48 毫克/公斤）、钾含量（150 毫克/公斤）以及土壤电导率（1420 微西门子/厘米）。
*   **Odoo 数据持久化与施肥任务触发**：
    Odoo 在接收到该数据包后，快速匹配 DevEUI 到设备卡片，并将指标写入时序数据库。如果连续三次测得的氮、磷、钾元素水平低于设定的农艺目标值（根据不同的作物生育阶段自适应匹配），系统会在后台自动生成一条变量施肥建议，并提示技术员一键生成对应的施肥任务（Mission）。

### 2a.2.3 无人机精准飞防任务调度规程 (UAV Precision Spraying SOP)

*   **飞防任务生成与轨迹分发控制**：
    大田发生病虫害风险时，植保主管在 Odoo 系统中配置植保飞防任务。系统将自动调用 `farm_ai` 轨迹引擎，生成包含航路点和变频变流量喷洒指令的数据集，派发至大疆或极飞无人机网关。
*   **飞防指令核心要素**：
    飞防指令包含任务唯一编码（Mission ID）、无人机硬件序列号、执业飞手操作执照号、所选药剂配方编码（Recipe Code）以及安全间隔期（PHI，例如 15 天）。飞防技术参数中，严格规定了喷洒流量（例如每分钟 3.5 升）、无人机在作物冠层上方的飞行相对高度（例如 2.5 米）、以及最大飞行地速（例如每秒 5.0 米）。
*   **航路轨迹航段定义**：
    轨迹数据定义了一组严格的 GPS 航路点坐标，包含航点序号、纬度、经度、相对起飞点的三维相对高度以及该航点上要执行的物理动作。动作包括：起飞升空（TAKEOFF）、降高切入（START_SPRAYING）、匀速喷洒作业（SPRAYING）、关闭作业喷嘴（STOP_SPRAYING）以及自动返航降落（LAND）。
*   **无人机硬件执行与状态写回**：
    无人机接收到上述指令后，由物理主控板控制旋翼和无刷药泵。在实际执行作业时，无人机的 GPS 网卡会持续向 Odoo 物理网口回传当前经纬度与剩余药量。如果发生风偏漂移或药尽，系统将在 Odoo 界面高频弹框报警，并在该飞防任务中留下完整的异常日志记录。

## 2a.3 业务拦截与 GxP 合规准入网关 (ORM Business Interception)

为了通过国家主粮 GxP（良好大田规范）合规，系统设立了药安期拦截规则。如果地块在安全间隔期（PHI）内被强行采收并推上地磅，系统将在底层事务执行中强行拦截报错，防止有毒作物漏出。

### 2a.3.1 准入控制步骤 (SOP Setup)

*   **配置阶段**：导航至农资配方与 GxP 安全红线规则库，将特定杀虫剂安全间隔期设为 `15` 天。
*   **记录阶段**：无人机完成喷洒时，向地块关联的种植周期记录最后施药时间戳。
*   **执行阶段**：采收卡车开上地磅（`agri.weighbridge.log`），录入地块、毛重并点击“验证（Validate）”时，系统启动自动审核。

### 2a.3.2 药残合规地磅验证控制规程 (GxP PHI Weighbridge SOP)

*   **地磅称重录入交互 (UI Weighbridge Entry)**：
    采收卡车开上物理地磅，地磅仪通过 RS-232 串口/网口将称重数据传输至地磅房 Odoo 系统。称重操作员打开“地磅过磅单”表单，新建记录，选择当前的种植周期，录入车牌号码、毛重（千克）与皮重（千克）。系统自动计算出净重，此时过磅单状态为“草稿”。
*   **验证动作与底层事务行锁控制 (Transaction & Row Locking)**：
    调度执行过磅单上方的“验证地磅（Validate Weighbridge）”按钮。系统瞬间在 PostgreSQL 数据库中对该种植周期行执行 `FOR UPDATE` 显式行锁锁定，阻断任何其他并发事务对该周期数据的脏读，防止高频过磅时绕过合规拦截。
*   **自动施药记录检索逻辑 (Pest Control History Retrieval)**：
    系统在后台快速搜索该种植周期地块下已完工（done）的植保施药任务，按施药日期倒序排列，提取最近一次的化学农药喷洒日期。
*   **安全间隔期断言与物理拦截机制 (Assertion & Rollback)**：
    系统计算当前称重日期与最后施药日期之间的实际天数差，并获取种植周期预设的安全间隔期（PHI）下限值。如果实测天数差小于安全间隔期，系统会触发强拦截机制，抛出“安全间隔期不满足（ValidationError）”异常。
    该异常将直接在 Odoo 界面弹出红色高亮阻断框，显示警告信息（例如：当前地块最后施药日期为 2026-08-10，实测安全间隔仅为 8 天，未达到 15 天合规红线，严禁违规混入主粮仓储系统！车牌号：辽A-XXXXX）。此操作不仅会阻断状态流转，还会物理回滚整个数据库过磅事务，确保没有任何不合规的仓单生成，且地磅放行道闸保持关闭状态。

## 2a.4 混合收割与物料谱系溯源 (Harvest & Matter Genealogy)

大田粮食（如小麦、玉米）采收通常具有 `N:1 Blending`（多个地块的收割卡车物料，汇入同一个大型钢板仓 Silo）的特征。

### 2a.4.1 混合物料物理配平 (N:1 Silo Blending Chart)

```text
 ┌──────────────────────┐
 │ PARCEL-01 (15,000kg) │ ───┐
 └──────────────────────┘    │
 ┌──────────────────────┐    ├─► [ Silo 混合计算引擎 ] ─► 最终 LPN-SILO-01 (43,000kg)
 │ PARCEL-02 (20,000kg) │ ───┤   - 加权计算累计农残留        - 自动分摊总碳足迹 (Scope 1)
 └──────────────────────┘    │   - 锁定最终理化指标数据      - 颁发溯源 Merkle 证明
 ┌──────────────────────┐    │
 │ PARCEL-03 (8,000kg)  │ ───┘
 └──────────────────────┘
```

### 2a.4.2 混合物料谱系溯源数据报送规程 (Silo Blending Traceability SOP)

*   **大型钢板仓混合物料核算流程 (Silo Blending Calculation)**：
    当来自不同地块、不同种植周期的采收卡车将物料倾卸入同一个大型筒仓（Silo）中时，Odoo 溯源引擎根据投入的地磅净重，自动执行 N:1 混合物料配平核算。
*   **混合溯源报文主要数据域 (Genealogy Report Fields)**：
    为了向国家粮食安全与农政溯源平台报送合规资产，系统会自动导出一份混合追溯报文。报文明确指明了目标筒仓的唯一物料箱码（Target Silo LPN，例如 LPN-SILO-NORTH-01）、农产品物理商品类型（例如：一级黄玉米）、混合日期与时间、以及混合后的总重量（例如 43,000.0 公斤）。
*   **谱系溯源明细拆解 (Pedigree Breakdown)**：
    报文的溯源谱系数组中，精确拆解了每一路源头物料的贡献详情：包括来源地块编码、来源种植周期、贡献的净重量（以千克为单位）、在该筒仓中所占的混合比例（例如 34.88%），以及最后施药后的残留量估算（以 ppm 为单位）。
*   **加权理化指标与碳足迹核算 (Weighted Metrics & Carbon Footprint)**：
    报文终段汇总了加权计算后的混合理化指标，包括加权平均含水率（例如 13.4%）、杂质纯度百分比、加权平均化学农药残留水平（例如 0.0088 ppm，完全低于食用安全标准），以及自动分摊分派的 Scope 1 总生产碳足迹（例如每吨玉米折合 42.5 公斤二氧化碳）。上述数据生成后将通过 API 自动进行加密签名上报，确保粮油企业能实现全过程、可追溯的高可信绿色合规审计。

## 2a.5 异常排查与常见自愈 (Troubleshooting)

大田运行期间，各种无人机飞行、LoRa 掉线及地磅安全阀异常排除矩阵如下：

| 错误代码 (Error Code) | 硬件/PLC 异常现象 (Symptom) | 根本原因 (Underlying Cause) | 排查及自愈步骤 (Remediation Step) |
| :--- | :--- | :--- | :--- |
| **ERR-FLD-001** | LoRaWAN 土壤传感器长时间未上报 | 传感器电池电量耗尽或大田物理网关死机。 | 现场用万用表检测网关 12V 馈电；检查 Chirpstack 节点的 DevEUI 秘钥签名是否过期。 |
| **ERR-FLD-002** | NDVI 卫星影像 Webhook 报错 403 | 卫星平台 API 调用的 Hmac SHA256 签名校验错误。 | 重新进入 Odoo 开发者接口，更新 API Secret 秘钥对。 |
| **ERR-FLD-003** | 无人机任务报 “BOUNDARY_VIOLATION” 停飞 | 无人机 GPS 轨迹超出地块 PostGIS 地理围栏。 | 打开地图，调用 `ST_Buffer` 为多边形边界设置 1 米向内安全收缩半径。 |
| **ERR-FLD-004** | 地磅点击保存时无限旋转卡死 | 称重仪 TCP/IP 转串口服务器波特率不匹配，或行锁事务超时。 | 重启串口服务器，在 Odoo 服务器中配置 `agri.weighbridge.log` 并发事务等待时间不超过 5 秒。 |



### 📐 物理数学计算模型：累计有效积温 (GDD) 与 PHI 安全拦截

Agri-OS 在大田种植周期中使用以下两个物理计算公式在底层执行实证运算：

1. **有效积温累计模型 (Growing Degree Days - GDD)**:
   [ GDD_day ] = MAX( ( [ T_max ] + [ T_min ] ) / 2 - [ T_base ], 0.0 )
   [ GDD_total ] = SUM( [ GDD_day_i ] )
   *   `T_max`, `T_min`: 卫星和 LoRaWAN 田间实测的每日最高与最低气温。
   *   `T_base`: 作物生物学生长基准温度（例如大豆一般设定为 10.0°C）。

2. **安全间隔期 (PHI) 强校验规则**:
   [ Days_since_spraying ] = [ Weighbridge_timestamp ] - [ Last_spray_timestamp ]
   ASSERT [ Days_since_spraying ] >= [ PHI_required ]
   *   若断言失败，数据库事务直接回滚（ROLLBACK），阻断地磅并关闭放行道闸。
