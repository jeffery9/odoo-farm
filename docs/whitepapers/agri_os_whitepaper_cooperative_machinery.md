## 2o.1 基础设置与农机台账空间登记 (Setup & Registration)

农业合作社的核心是多成员、跨地块的农机高效率共享。系统通过 `farm_equipment` 与 `farm_operation` 模块联合管理重型农机资产、共享调度任务单及配给公式。

### 2o.1.1 农机共享台账与调度任务建立业务规程 (Machinery Setup SOP)

*   **建立合作社农机物理资产台账**：
    1.  登录系统，导航至“农机共享 -> 农机装备台账”菜单，系统触发唯一性档案初始化事务（Transaction Initialization）。
    2.  输入唯一的物理装备编码（例如：EQP-TRACTOR-05）。
    3.  输入直观的农机名称（例如：合作社雷沃 200 马力重型拖拉机）。
    4.  指定农机设计的“每小时额定作业面积（亩/小时）”（例如：15.0 亩/h）。
    5.  关联绑定该设备集成的“GPS 物联网车载网关”（例如：五号车载北斗定位网关）。
    6.  点击“保存”，系统会自动建立农机资产档案，并初始化状态为“空闲”。

*   **初始化农机共享调度周期批次**：
    1.  导航至“农机调度单”菜单并点击“新建”。
    2.  输入调度任务名称（例如：2026年秋收吉林五常外围马铃薯跨地块机械采收调度单）。
    3.  指定本次调度的“作业服务配方”（detailed_type，例如：重型收获马铃薯标准耕作配方）。
    4.  录入计划服务的“总作业面积（亩）”（例如：300.0 亩）。
    5.  关联绑定对应的物理农机。
    6.  点击“保存”，系统流水号发生器会在表单上方生成唯一的调度单号（例如：MMS-2026-0012），并将当前状态初始化为“草稿”。

### 2o.1.2 界面操作与布局说明 (UI Layout & Interaction)

*   **列表视图（List View）**：
    在农机调度单列表视图下，展示调度单号、调度名称、物理农机、计划面积、实测轨迹面积、作业费用单价及当前状态。行数据根据状态动态变色：草稿状态以蓝色信息气泡显示，“作业调度中（Dispatching）”状态以绿色成功样式标记。
*   **状态机推进与空间重叠校验（State Machine & GIS Overlap Checks）**：
    表单顶部设计有动作控制按钮和进度状态。状态机包括“草稿”、“进行中”、“暂停”、“已完工”。点击“启动调度”时，系统验证关联的地块空间是否 100% 存在于合作社确权 WKT 多边形网格内，通过后状态推进为“进行中”。
*   **字段只读控制与 Chatter 审计（Read-only Constraints）**：
    为了保证调度严肃性，一旦调度单状态切换至“进行中”，农机资产、作业服务配方、总作业面积将自动锁定。表单下方的 Chatter 会高频记录农机北斗轨迹坐标、小时级燃油消耗、以及农机手提交的安全日报。

## 2o.2 物联网架构与北斗遥测闭环 (GPS & Telemetry Loop)

共享重型农机集成有车载北斗双模定位终端和柴油流量计，通过 4G 网关高频上行高精度的轨迹、航向角、小时级燃油消耗及发动机工况。

### 2o.2.1 北斗高精度轨迹与工况遥测 SOP (GPS Telemetry SOP)

*   **北斗高精度轨迹轮询规程**：
    安装在拖拉机上的北斗/GPS 双模车载网关，通过标准的 JT/T 808 交通部通信协议，以 `5 秒` 的极高频率向 Odoo 后台推送经纬度坐标。
*   **核心遥测指标解释**：
    1.  **实测北斗定位经纬度**：网关实时读取卫星定位，系统后台结合 PostGIS 空间库，在 Odoo 调度大屏上动态渲染出拖拉机的物理行驶轨迹，并自动积分扣减重叠面积。
    2.  **实测柴油瞬时流量**：网关读取发动机燃油传感器。
    3.  **作业故障PLC自动报警**：当发动机液压系统油压异常或发动机转速瞬间低于设定安全阈值时，自动向调度终端拉起报警。

### 2o.2.2 农机车载事件推送报文 (HTTP IoT GPS Payload)

当传感器探测到农机越界出确权区或发生故障时，网关会自动向系统的 API 接口推送设备编码、时间戳、物理检测指标：经度、纬度、航向角（度）、小时级油耗（升/小时）、液压系统压力（bar）以及故障诊断码（DNC）等明文报文。

Odoo 接收到报文后，会将指标自动写入该农机资产的动态时钟中，用作后续费用结算和设备折旧的直接物证。

## 2o.3 业务拦截与 GxP 合规准入网关 (ORM Business Interception)

合作社农机调度最核心的安全边界是防止同一台农机在同一个时间段、物理重合的地块上发生冲突调度（Overlap）。系统设立了“农机双重预约重合冲突自动行级排他锁定”网关。

### 2o.3.1 准入控制步骤 (SOP Setup)

1.  **设定阈值**：调度主管在 Odoo“参数配置”中，设定时间冲突的最大重合安全容差（默认值为 `0 分钟`）。
2.  **验证拦截**：当技术员在 Odoo 尝试对调度单点击“确认调度”时，系统启动自动审核。
3.  **安全判定**：
    *   **绿色状态（无感放行）**：当前预约时段内，这台重型拖拉机无任何其他地块的作业安排。系统放行。
    *   **红色拦截（行级锁死阻断）**：若发现农机已被另一张调度单预约，且时间重叠，系统触发强制拦截。

### 2o.3.2 农机双重冲突调度强拦截与物理隔离规程 (GxP Conflict Gate SOP)

1.  **提交农机调度单**：当技术员建立调度并点击“确认调度”时，系统启动底层检验。
2.  **数据库行锁锁定**：系统瞬间在数据库对该农机设备记录执行 `SELECT FOR UPDATE NOWAIT` 行级排他锁锁定，阻止并发修改该农机的预约日程表，阻断调度单的确认。
3.  **自动检索实时调度日程**：
    *   系统检索本农机设备关联的所有时序调度作业日志。
4.  **触发红色安全阀硬锁**：
    *   若发现时间空间发生物理冲突，系统强制抛出“该拖拉机在当前时段存在重叠作业任务”安全合规警告。
    *   异常将直接在操作员手持终端上弹出高亮红色阻断框，强制回滚整个验证事务，不产生任何允许调度或作业的实体调度单。
    *   **设备物理自愈动作**：系统自动向车载北斗终端下发 0（锁定点火变频继电器）信号，并在大屏上自动重新规划备用农机调度方案。

## 2o.5 异常排查与常见自愈 (Troubleshooting)

重型农机共享期间，GPS 丢包、北斗天线偏移及设备网络故障排除矩阵如下：

| 错误代码 (Error Code) | 硬件/PLC 异常现象 (Symptom) | 根本原因 (Underlying Cause) | 排查及自愈步骤 (Remediation Step) |
| :--- | :--- | :--- | :--- |
| **ERR-EQP-001** | 车载北斗无法上报坐标或漂移严重 | 北斗吸顶蘑菇头天线被大田泥土/灰尘物理遮挡，或电磁屏蔽网未单端接地。 | 手动擦拭北斗天线罩表面泥沙和浮土；检查并紧固车载馈线天线水晶头。 |
| **ERR-EQP-002** | 提货页面提示 “MACHINERY_CONFLICT” 警告 | 同一台农机在当前时段存在空间/时间重叠调度，系统强制锁死。 | 自动锁死车辆点火离合器继电器，自动提示调度员在日历视图下重排。 |
| **ERR-EQP-003** | 边缘北斗网关上报 “JT808_RESPONSE_TIMEOUT” | 车载 SIM 卡天线接触不良，或 4G 网络信号高频跌落。 | 紧固 SIM 卡插槽防护铜片；手动重启车载 Modbus 网卡进行信号自愈连接。 |

### 📐 物理数学计算模型：共享农机折旧系数与公摊计费算法

Agri-OS 在合作社农机共享运营中，采用以下公式核算机械损耗与跨地块公摊费用：

1. **农机折旧损耗系数 (Actual Operating Depreciation Index)**:
   [ Depreciation_Cost_day ] = [ Base_Depreciation_daily ] * ( 1.0 + [ Wear_multiplier ] )
   [ Wear_multiplier ] = ( [ Actual_Fuel_litres ] / [ Work_duration_hours ] ) * [ Load_factor ]

2. **多地块联合作业公摊计费公式**:
   [ Bill_For_Parcel_i ] = [ Total_operating_cost ] * ( [ Area_of_parcel_i (mu) ] / [ Total_combined_work_area (mu) ] )
