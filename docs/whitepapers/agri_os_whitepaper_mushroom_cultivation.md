## 2d.1 基础设置与菌种注册 (Setup & Registration)

工厂化菌菇繁育高度依赖于出菇房空间网格定位和严格的菌种（Spawn）世代控制。系统通过 `farm_mushroom` 模块管理菌种、培养床及设施绑定。

### 2d.1.1 菌菇繁育批次建立业务规程 (Mushroom Batch Setup SOP)

*   **建立菌种繁育批次**：
    1.  登录系统，导航至“设施菌菇 -> 繁育批次”菜单，点击“新建”。
    2.  输入直观的批次名称（例如：白玉菇一号特级栽培繁育批次）。
    3.  选择对应的“原菌株/孢子母本”（product.product），系统会自动在后台限制只允许选择符合菌株分类的原种（detailed_type 为消耗品/高纯无菌菌株）。
    4.  选择当前栽培的物理“繁育代次（Spawn Generation）”，支持：
        *   `母种一级 (g1_mother)`：试管斜面培养阶段。
        *   `原种二级 (g2_grain)`：麦粒或木屑瓶装扩大培养阶段。
        *   `栽培种三级 (g3_cultivar)`：用于接种栽培袋的最终大批生产代次。
    5.  关联该批次对应的物理“设施定位/出菇床架”，确保每个生物资产拥有明确的立体栽培架空间定位。
    6.  录入本次栽培接种的“接种包数/培养袋数”（例如：10000 袋）。
    7.  点击“保存”，系统会自动检索后台的流水号发生器，在界面顶部生成全局唯一的菌菇批次号（例如：MRB-2026-0012）。

### 2d.1.2 界面操作与布局说明 (UI Layout & Interaction)

*   **列表视图（List View）**：
    在菌菇繁育批次列表视图下，展示菌菇批次号、批次名称、母本菌株、繁育阶段、关联栽培床、接种袋数和状态。利用原生布尔值样式装饰器，数据行将根据阶段自适应着色。草稿状态以淡蓝色气泡显示，培养中（Cultivating）状态以绿色成功样式标记，采收中（Harvesting）以橙色高亮。
*   **状态机推进（State Machine Progression）**：
    表单顶部设计有动作控制按钮和面包屑进度。批次刚建立时状态为“草稿”。点击“启动接种培养”按钮，系统验证菌株和培养床绑定齐全后状态推进为“培养中”；点击“启动采收”按钮，状态推进为“采收中”；采收全部潮次后，点击“完工关闭”完成全周期，状态变更为“已完工”。
*   **字段只读控制（Read-only Constraints）**：
    为防止数据在培养中途被非授权修改，一旦批次推进到“培养中”状态，原菌株母本、接种袋数及繁育代次将自动变为只读锁定状态。在“已完工”阶段，表单内所有字段将永久只读锁定。

## 2d.2 物联网架构与遥测闭环 (IoT & Telemetry Loop)

出菇房微气候环境参数通过 Modbus RTU 工业 PLC 控制器进行高频数据采集和变频通风调控。

### 2d.2.1 出菇房温湿度与二氧化碳 PLC 通信 SOP (Modbus IoT Integration)

*   **PLC 通信网关轮询规程**：
    安装在出菇房立体床架上的温湿度及二氧化碳（CO2）传感器，通过 Modbus 协议将气体与温湿度高频数据推送至 Odoo 后台时序表。
*   **核心遥测指标解释**：
    1.  **实测相对湿度**：网关以寄存器数据读取实测相对湿度值，乘以 `0.1` 缩放因子后，在 Odoo 界面渲染出高精度的百分比（例如：92.5% 相对湿度，出菇房需维持极高空气湿度）。
    2.  **实测 CO2 浓度**：网关读取二氧化碳寄存器值（ppm，例如：850 ppm），这是控制菌盖和菌柄发育比例的核心指标。
    3.  **变频风机控制**：网关根据实测 CO2 浓度值自动下发变频控制信号。当浓度超标时，向变频风机 PLC 下发变频功率指令，调整风机频率。

### 2d.2.2 出菇房遥测状态上行报文 (HTTP IoT Telemetry Payload)

当环境参数超出预警限时，边缘网关会自动向系统的 API 接口推送传感器名称、时间戳、物理检测指标：温度、湿度、二氧化碳浓度、当前微弱光照（例如：100.0 Lux）以及变频排风机的工作频率（赫兹）等明文报文。

Odoo 接收到报文后，会将指标关联至该菇房承载的所有菌菇栽培批次上，用以分析环境舒适度得分。

## 2d.3 业务拦截与 GxP 合规准入网关 (ORM Business Interception)

在菌菇工厂化生产中，栽培培养基（菌棒）的灭菌质量（达到 121 摄氏度及特定高压）是防止后续链孢霉等杂菌污染的关键。系统设立了“高压灭菌温度物理联锁”网关。

### 2d.3.1 准入控制步骤 (SOP Setup)

1.  **设定阈值**：生产主管在 Odoo“参数配置”中，设定灭菌釜强制物理放行红线：温度必须达到 `121.0` 摄氏度，且维持时间不得低于 `30` 分钟。
2.  **执行验证**：灭菌锅炉工在灭菌单（`agri.sterilization.log`）中录入压力釜号、当前温度及保温天数。
3.  **安全判定**：
    *   **绿色状态（自动解锁放行）**：实测温度达到或超过 121°C 维持 30 分钟。系统在数据库对该批菌棒解锁，并自动通知气动阀，允许物理安全门开启。
    *   **黄色警戒（人工说明）**：温度处于 120°C 到 121°C 之间，系统弹窗发出警告。锅炉工必须在确认日志中录入“热工偶温差排查”说明，方可继续激活。
    *   **红色拦截（事务锁死）**：当实测最高灭菌温度低于 `120.0` 摄氏度，或者锅炉压力传感器显示过载警告时，系统触发强制拦截网关。

### 2d.3.2 压力釜灭菌温度强制拦截与自愈控制规程 (GxP Sterilization Gate SOP)

1.  **提交灭菌验证**：当操作员建立灭菌报表并点击“验证放行”时，系统启动底层检验。
2.  **数据库行锁锁定**：系统瞬间在数据库对该灭菌记录执行 `FOR UPDATE` 行级锁定，防止并发修改灭菌数据。
3.  **自动检索实时温感历史**：
    *   系统调用 API 检索该压力釜在本次周期中上报的所有温度序列，检查 121°C 以上的连续保持时间。
4.  **触发红色安全阀硬锁**：
    *   若不满足 121°C 保持 30 分钟，系统强制抛出“高压灭菌温度严重不足”安全警告。
    *   异常将直接在操作员操作屏幕上弹出高亮红色阻断框，强制回滚整个验证事务，不产生任何允许出炉或转入无菌接种室的出库调拨单。
    *   **设备物理自愈动作**：系统自动将对应灭菌釜的状态变更为“超压/温度告警”，向灭菌釜电子安全锁继电器下发 0（保持关闭）信号，使物理门保持关闭，并自动拉起自愈警报，启动二次高温高压自动补温补偿机制。

## 2d.4 潮次采收与物料谱系溯源 (Harvest & Matter Genealogy)

工厂化菌菇具有典型的 **多潮次采收（Flush Cycles）**和 **产量递减（Yield Decay）**特征（通常第一、二潮质量最好，第三潮品质递减）。

### 2d.4.1 多潮次采收与产量衰减图谱 (SOP Flush Decay Chart)

```text
 [ 栽培菌棒批次 ]
        │
        ├─► 第一潮采收 (Flush 1 - 占总重 50% 优质) ──► 自动匹配 A 级品质包装
        ├─► 第二潮采收 (Flush 2 - 占总重 30% 优质) ──► 自动匹配 B 级品质包装
        └─► 第三潮采收 (Flush 3 - 占总重 20% 普通) ──► 自动匹配 C 级降级包装（加工料）
```

### 2d.4.2 潮次谱系溯源数据报送规程 (Flush Genealogy Traceability SOP)

*   **多潮次采收登记流程**：
    当出菇房技术员对某一栽培床的白玉菇进行采收时，在 PDA 终端创建采收记录单，选择当前栽培批次，并指明当前采收的“潮次序号（Flush Number）”（如：第 1 潮、第 2 潮、第 3 潮）。
*   **潮次生命周期与产量衰减算法**：
    Odoo 农业核心模块会根据历史潮次数据自动计算当前栽培批次的“潮次生命力得分”。当发现当前已经是第 3 潮采收时，系统会自动在采收包上强制写入品质自适应评级（例如将第 3 潮产品评级默认为“B级/降级加工料”）。
*   **碳足迹分摊与包装箱条码分发**：
    系统根据采收净重分摊前期的基质、灭菌、出菇房高压排风的 Scope 1 总能源消耗，并向最终包装箱分发唯一的包物料溯源箱码标签（LPN）。
*   **一箱一码双向追溯证书展现**：
    超市消费者通过手机扫描白玉菇包装盒上的二维码标签。系统自动连接到开放追溯平台，展现该盒菌菇的可信履历：包括它的精确采收时间与采收潮次（如：第 1 潮精选）、出菇房温湿度及 CO2 历史曲线、接种接种单、基质配方、以及最核心的 121°C 高温灭菌温度达标时间（如：121.2°C 保持 45 分钟，安全放行）。让消费者清晰感知高品质工业化菌菇的食品安全，提升产品溢价。

## 2d.5 异常排查与常见自愈 (Troubleshooting)

菌菇环控运行期间，灭菌门锁卡死、二氧化碳超标及传感器失联排除矩阵如下：

| 错误代码 (Error Code) | 硬件/PLC 异常现象 (Symptom) | 根本原因 (Underlying Cause) | 排查及自愈步骤 (Remediation Step) |
| :--- | :--- | :--- | :--- |
| **ERR-MUSH-001** | 出菇房二氧化碳（CO2）超标，排风机未运转 | 排风变频器 PLC 继电器控制端子松动或总线失联。 | 检查变频器模拟量输入引脚（应为 4-20mA 信号）；手动强启 PLC 变频继电器并调整频率为 50Hz。 |
| **ERR-MUSH-002** | 灭菌单页面提示 “STERILIZATION_FAILED” 报错 | 物理传感器检测到锅炉压力或温度低于 120°C 警戒线，事务回滚。 | 检查压力釜物理安全泄压阀是否漏气；更换不达标的电加热管，执行二次高温蒸汽强制补温。 |
| **ERR-MUSH-003** | 边缘网关上报 “PLC_MODBUS_CRC_ERROR” 警告 | RS-485 信号线受现场动力电机高频电磁干扰。 | 使用双绞屏蔽线重新布线，将屏蔽层单端接地，并增加 120 欧姆终端匹配电阻。 |
