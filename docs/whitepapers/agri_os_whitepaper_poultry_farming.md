## 2h.1 基础设置与禽舍登记 (Setup & Registration)

设施羽禽业务高度依赖于禽舍网格化笼位划分和精确的日龄段（Day-of-Age）营养日记控制。系统通过 `farm_livestock` 模块管理笼位资产、入栏批次及饲料日粮配比。

### 2h.1.1 禽舍笼位入栏建立业务规程 (Poultry Registration SOP)

*   **建立禽舍与网格化笼位档案**：
    1.  登录系统，导航至“设施羽禽 -> 禽舍笼舍台账”菜单，系统触发唯一性档案初始化事务（Transaction Initialization）。
    2.  输入直观的禽舍名称（例如：智能化蛋鸡育成一号舍）。
    3.  输入唯一的禽舍编码（例如：POULTRY-HOUSE-04）。
    4.  选择当前禽舍的“物理笼位划分（Grid Layout）”，支持：
        *   `A 区上层 (a_top)`：高位通风良好保温区。
        *   `B 区中层 (b_middle)`：核心高密采食监控区。
        *   `C 区下层 (c_bottom)`：底层粪便清理联动区。
    5.  录入设计最大“容纳羽数”（例如：20000 羽）。
    6.  点击“保存”，系统会自动分配唯一禽舍编码。

*   **初始化雏鸡入栏繁育批次**：
    1.  导航至“羽禽繁育批次”菜单并点击“新建”。
    2.  输入批次名称（例如：海兰褐蛋鸡 2026 夏季入栏育成批次）。
    3.  选择或指定雏鸡的“品种来源”（detailed_type 为消耗品/高产品种）。
    4.  选择入栏时的“雏鸡日龄（Day of Age）”（例如：1 日龄）。
    5.  关联上述登记的物理禽舍及对应网格。
    6.  录入本次入栏的“初始总羽数”（例如：18000 羽）。
    7.  点击“保存”，系统会自动匹配流水号发生器，在界面顶部生成唯一的羽禽批次号（例如：PLB-2026-0024），并将状态初始化为“草稿”。

### 2h.1.2 界面操作与布局说明 (UI Layout & Interaction)

*   **列表视图（List View）**：
    在羽禽繁育批次列表视图下，展示羽禽批次号、名称、雏鸡品种、日龄、入栏羽数、昨日产蛋率以及当前状态。利用原生布尔值样式装饰器，数据行将根据阶段自适应着色。育雏期（Brooding）状态以蓝色信息气泡显示，“产蛋中（Laying）”状态以绿色成功样式标记。
*   **状态机推进（State Machine Progression）**：
    表单顶部设计有动作控制按钮。批次刚建立时状态为“草稿”。点击“激活入栏”，状态推进为“育雏生长中”；点击“启动产蛋期”，状态推进为“产蛋中”；淘汰出栏时，点击“完工清棚”完成全周期，状态变更为“已完工”。
*   **字段只读控制（Read-only Constraints）**：
    为了保证生物数据物理防篡改，一旦批次推进到“产蛋中”状态，雏鸡品种、入栏初始羽数及日龄将自动变为只读锁定状态。在“已完工”阶段，表单内所有字段将永久只读锁定。

## 2h.2 物联网架构与遥测闭环 (IoT & Telemetry Loop)

禽舍内部微气候环境参数通过 Modbus RTU 工业 PLC 控制器进行高频数据采集和变频通风调控。

### 2h.2.1 禽舍氨气与温湿度 PLC 通信 SOP (Modbus IoT Integration)

*   **PLC 通信网关轮询规程**：
    安装在禽舍不同高度、不同网格笼位上的温湿度及有害氨气（NH3）传感器，通过 Modbus 协议将气体指标高频推送至 Odoo 后台时序表。
*   **核心遥测指标解释**：
    1.  **实测氨气（NH3）浓度**：网关以寄存器数据读取实测氨气浓度值，乘以 `0.1` 缩放因子后，在 Odoo 界面渲染出高精度的百万分比浓度（例如：12.4 ppm，超过 20 ppm 将严重诱发禽类呼吸道疾病）。
    2.  **实测二氧化碳（CO2）浓度**：网关读取二氧化碳寄存器值。
    3.  **变频排风机控制**：网关根据实测氨气与二氧化碳浓度值自动下发变频控制信号。当氨气浓度超标时，向变频风机 PLC 发送功率指令，调整风机频率。

### 2h.2.2 禽舍状态上行报文 (HTTP IoT Telemetry Payload)

当环境参数超出预警限时，边缘采集网关会自动向系统的 API 接口推送禽舍编码、时间戳、物理检测指标：温度、湿度、氨气浓度、二氧化碳浓度、当前微弱光照以及变频排风机的工作频率等明文报文。

Odoo 接收到报文后，会将指标关联至该禽舍承载的所有羽禽栽培批次上，用以分析禽舍环境健康度。

## 2h.3 业务拦截与 GxP 合规准入网关 (ORM Business Interception)

在羽禽养殖中，每日的累积死淘率（Mortality Rate）是监控禽流感等烈性传染病的核心窗口。系统设立了“日死淘率超红线自动行级排他锁定”网关。

### 2h.3.1 准入控制步骤 (SOP Setup)

1.  **设定阈值**：生产主管在 Odoo“参数配置”中，设定羽禽允许的最大日死淘率上限（默认值为 `3.00%`）。
2.  **日常报损**：饲养员在每日清晨巡检时，通过手持终端记录当日的死淘羽数。
3.  **安全判定**：
    *   **绿色状态（无感放行）**：累计日死淘率低于 `1.00%`，允许进行常规的饲喂、清粪和正常蛋品包装。
    *   **黄色警戒（人工说明）**：日死淘率处于 `1.00%` 到 `3.00%` 之间，系统弹窗发出警告。饲养员必须在确认日志中录入“局部挤压或热应激”说明，方可继续激活。
    *   **红色拦截（行级锁死阻断）**：当某一育成批次的累计日死淘率突破 `3.00%` 时，系统触发强制拦截网关。

### 2h.3.2 死淘率严重超标强拦截与物理隔离规程 (GxP Mortality Gate SOP)

1.  **提交死淘报损单**：当饲养员建立“羽禽死淘报损单”并点击“验证”时，系统启动底层检验。
2.  **数据库行锁锁定**：系统瞬间在数据库对该羽禽批次执行 `SELECT FOR UPDATE` 行级锁定，防止并发修改死淘数据，阻断清棚或蛋品出库单的开具。
3.  **自动计算累计日死淘率**：
    *   系统检索该批次当日所有的死淘报损记录，并折算：`日死淘率 = 当日累计报损羽数 / 存栏总羽数`。
4.  **触发红色安全阀硬锁**：
    *   若计算结果超过 3%，系统强制抛出“禽群死淘率严重突破安全红线”安全警告。
    *   异常将直接在操作员手持终端上弹出高亮红色阻断框，强制回滚整个验证事务，不产生任何允许出库或转入包装车间的出库调拨单。
    *   **设备物理自愈动作**：系统自动将对应禽舍的状态变更为“疫情隔离”，向自动上料机、集蛋带继电器下发指令，强制断电停止工作；同时，自动向排粪传送带和舍内消毒阀发送指令，强制启动舍内无死角喷雾消毒自愈。

## 2h.4 蛋品集蛋与物料谱系溯源 (Harvest & Matter Genealogy)

蛋品采收具有典型的 **每日高频集蛋（Egg Harvesting）**特征，集蛋带采集的蛋品属于 **1:N Fission**（原蛋分裂为特级蛋、普通蛋、脏破蛋等不同包装 LPN）。

### 2h.4.1 蛋品集蛋与分选裂变图谱 (SOP Egg Harvesting Chart)

```text
 [ 自动集蛋传送带 ] ──► [ 光学裂纹色选机 ] ──► [ 1:N 包装分裂 ] ┬──► 特级品牌蛋-A (冷链包装)
                                                               └──► 普通包装蛋-B (批发包装)
```

### 2h.4.2 蛋品集蛋谱系分裂追踪业务规程 (Egg Genealogy Traceability SOP)

*   **集蛋与分选登记流程**：
    当自动集蛋带将蛋品送抵集蛋车间包装线时，操作员扫描传送箱条码，创建集蛋任务。
*   **指定母子系谱继承关系**：
    系统弹出集蛋裂变表单，自动读取母批次禽舍条码，并由操作员指定接种生成的包装箱成品批次代号。系统在后台通过遗传双向无环图（DAG），自动将母批次的代码作为“父节点”注入包装箱中，实现完全的生命历程继承。
*   **碳足迹分摊与一箱一码溯源证书颁发**：
    系统根据蛋品重量自动分摊前期禽舍饲料消耗、高能耗排风、清粪传送带的 Scope 1 总排碳。种子在完成包装后，操作员扫描出箱单。系统自动生成该箱蛋品的唯一身份证二维码标签。
*   **扫码追溯证书展现**：
    超市消费者通过手机扫描蛋盒上的二维码。系统展现该盒蛋品的可信履历：包括它的精确集蛋日期与鸡舍日龄、昨日产蛋率、昨日禽舍氨气与二氧化碳实时曲线、饲料消耗、以及最核心的禽舍日死淘率历史（如：0.05% 极佳安全状态放行）。让消费者清晰感知高品质绿色蛋品的食品安全。

## 2h.5 异常排查与常见自愈 (Troubleshooting)

设施羽禽运行期间，排风故障、氨气告警及传感器失联排除矩阵如下：

| 错误代码 (Error Code) | 硬件/PLC 异常现象 (Symptom) | 根本原因 (Underlying Cause) | 排查及自愈步骤 (Remediation Step) |
| :--- | :--- | :--- | :--- |
| **ERR-PLB-001** | 禽舍内二氧化碳及氨气浓度严重超标，风机卡死 | 变频器过载保护跳闸或排风扇皮带物理断裂。 | 检查变频器散热风扇和电容状态；手动更换排风扇皮带，手动合闸复位变频器。 |
| **ERR-PLB-002** | 报损单页面提示 “MORTALITY_CRITICAL” 警告 | 当日死淘率突破 3% 警戒红线，批次被全线锁定。 | 停止该禽舍一切集蛋带和喂料机运转，对操作员手持终端进行物理级消毒，并启动舍内无死角喷雾消毒。 |
| **ERR-PLB-003** | 边缘网关上报 “UPLINK_TIMEOUT_WARN” 警告 | 禽舍钢架结构屏蔽导致 Wi-Fi 信号异常丢失。 | 调整温室无线天线方向，加装室外型定向高增益中继天线提升 RSSI。 |

### 📐 物理数学计算模型：饲料转化率 (FCR) 与产蛋率指数

Agri-OS 在家禽养殖中采用以下公式执行日增重和绩效核算：

1. **饲料转化率 (Feed Conversion Ratio - FCR)**:
   [ FCR ] = [ Total_feed_consumed (kg) ] / [ Total_weight_gain (kg) ]
   *   FCR 数值越低，代表饲料转化率和经济效益越好。

2. **鸡群日产蛋率 (Laying Rate)**:
   [ Laying_Rate % ] = ( [ Total_eggs_collected ] / [ Total_laying_hens ] ) * 100
